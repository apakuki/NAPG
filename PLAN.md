# NAPG Starting Plan

NetAssure Protocol Guardian: autonomous Protocol Service Assurance agent for the Coinbase Base ecosystem. This document is the source-of-truth phased plan. Tick boxes as work lands. Update the architecture/library notes inline when reality drifts from the brief.

Reference: [CLAUDE.md](CLAUDE.md), [docs/architecture.md](docs/architecture.md).

## Operating principles

- Python 3.10+ for the agent core, Next.js in `frontend/`.
- MPC wallets only. Private keys never enter agent code. All signing goes through CDP TEE.
- Every autonomous decision writes a permanent audit record (the "why" must be recoverable).
- **Resilience posture: normal operations fail closed; emergency migration runs in a degraded-but-controlled mode.** NAPG's mission (protect funds during instability) and a blanket fail-closed gate can directly conflict — a fail-closed simulation gate can block the very rescue the agent exists to perform during a correlated outage. So the safety migration (`migrate_to_safe`, native transfer to the pre-pinned safe address) has a narrow, audited, human-approved override when its dependencies are degraded; everything else stays fail-closed. See [docs/runbooks/infra-outage.md](docs/runbooks/infra-outage.md) and [docs/runbooks/emergency-migration.md](docs/runbooks/emergency-migration.md).
- **Security is built into each layer as it lands, not bolted on at Phase 2.** Every phase has a Security subsection that must be checked before sign-off. See the cross-cutting baseline below.
- **Troubleshooting runbooks are part of the deliverable.** Every phase has a Troubleshooting subsection in the symptom -> likely cause -> diagnose -> fix format. Treat these as living docs.
- **Manual test procedures live in [docs/manual-tests/](docs/manual-tests/).** One file per phase. Update as features land.
- No emojis. Anywhere. Code, commits, README, UI.
- No defensive programming, no speculative features, no premature abstraction.
- Aim for 80% minimum unit coverage on backend modules; Playwright for frontend integration.
- Get user sign-off at the end of each phase before starting the next.

## Cross-cutting security baseline

These apply throughout the project, regardless of phase. Drift here is a release-blocker.

- **Secrets never in git.** `.env` is gitignored. Pre-commit secrets scan (gitleaks) wired in by Phase 1. CI re-scans every push.
- **Dependency CVE scanning.** `pip-audit` (agent) and `npm audit --audit-level=high` (frontend) run in CI; HIGH/CRITICAL findings fail the build.
- **Lockfile-pinned dependencies.** `uv.lock` and `package-lock.json` are committed. Dependabot keeps them moving.
- **MPC-only wallet operations.** No raw private keys, mnemonics, or signed payloads in logs, audit DB, or memory dumps. Any code path that touches signing material gets a code-review checklist tick.
- **Append-only audit log.** SQLite tables are write-once. Row-level HMAC (separate key) lands before mainnet so tampering is detectable.
- **Least-privilege API keys.** One key per environment, scoped to the minimum permissions. Rotated quarterly. Never shared across envs.
- **Redaction at log boundaries.** A single `redact()` helper strips known-sensitive fields before anything reaches stdout, files, or the audit DB.
- **Branch protection on `main`.** Required CI green. No force-push. Reviewed merges only once we leave solo-dev mode.
- **Threat-model delta at every sign-off.** "What new attack surface did this phase add and how do we handle it?" — answered in writing before the next phase starts.
- **Kill-switch from Phase 2 onwards.** A single signed message or env var halts all signing immediately.

### Troubleshooting
Symptom -> likely cause -> diagnose -> fix.

- **`uv sync` fails with "Python 3.10+ required"** -> uv didn't auto-install a compatible Python -> `uv python list` to see what's available -> `uv python install 3.12` then re-run `uv sync`.
- **`uv run pytest` says `ModuleNotFoundError: napg`** -> editable install missed -> `uv sync --reinstall` from inside `agent/`.
- **`ruff format --check .` fails in CI but passes locally** -> uncommitted formatter drift on another branch -> `uv run ruff format .`, commit, re-push.
- **`npm install` hangs or times out** -> registry/proxy issue -> `npm config get registry`, check network, retry with `--prefer-online`.
- **`npm run build` fails: "module not found" after dependency change** -> stale `.next` cache -> `rm -rf .next && npm run build`.
- **Vitest can't resolve `@/*` paths** -> alias mismatch in `vitest.config.ts` -> confirm `path.resolve(__dirname, "./src")` matches `tsconfig.json` `paths`.
- **Playwright e2e fails: "browser not installed"** -> chromium binary not downloaded -> `npx playwright install chromium` from `frontend/`.
- **CI fails on macOS-only line endings** -> CRLF crept in -> add `* text=auto eol=lf` to `.gitattributes`, re-normalise.
- **`.env` accidentally committed** -> immediately rotate every key in it, `git rm --cached .env`, force-push only after coordinating; treat all leaked keys as compromised.

### Troubleshooting
- **RPC heartbeat reports stale block height** -> provider lag or chain reorg -> cross-check against a second RPC; if both stale, mark provider degraded and switch fallback.
- **`web3.exceptions.TimeExhausted` on every call** -> provider throttling or down -> check provider status page, switch to fallback RPC, decrement rate-limit budget.

- **Seamless oracle freshness check always fails** -> price feed paused or oracle address changed -> compare against Seamless protocol docs; if confirmed paused, mark market degraded, do not migrate on stale-oracle alone.
- **Anthropic SDK returns HTTP 429** -> rate limit -> exponential backoff with jitter; persist last-good decision; alert if backoff >5 min.
- **Audit-log row missing `tx_hash` field** -> tx submitted but receipt poll timed out -> never delete the partial row; reconcile by tx hash in the next monitor cycle; log the reconciliation.
- **Sepolia faucet exhausted, wallet at zero** -> testnet wallet drained -> top up via Coinbase or Alchemy faucet; record the source in the runbook to track our test-funding pipeline.
- **Dashboard loads but shows no data** -> FastAPI endpoint returning 500 or CORS rejection -> hit endpoint directly with `curl`; check FastAPI logs; verify `next.config.ts` rewrites or CORS allowlist.
- **Tenderly simulation rejects a tx that succeeds onchain** -> simulation block stale -> set simulation block to `pending` or current head; re-run.

## Phase 2 (Wk 3): Security Layer

Wrap every signing path in AgentShield's 4-stage validation. Nothing reaches the wallet without passing all four gates.

### Substeps
- [x] Stage 1 - Intent Judge: LLM-side check that the proposed action matches the stated goal — `napg.agentshield.stages.intent_judge.build_intent_judge_stage(api_key=, client=, model=)` returns the Stage 1 callable. Separate Anthropic call with its own `JUDGE_SYSTEM_PROMPT` (ephemeral cache) and a `submit_verdict` tool returning `{verdict: agree|disagree|abstain, reason}`. Only `agree` passes; `disagree` fails closed with the judge's reason; `abstain` also fails closed (uncertainty is not consent). Structurally independent from `napg.reasoning` — different prompt, different tool, separate call — so a prompt-injection on the reasoner does not also poison the judge. 7 tests cover agree/disagree/abstain, missing-API-key, malformed response, system-prompt caching, and that the user message carries every intent field
- [x] Stage 2 - Policy Validation: per-tx caps, token allowlist, destination denylist, daily-spend ceiling — `napg.agentshield.stages.policy.build_policy_stage(policy, denylist, audit_log=, now_provider=)` returns the Stage 2 callable. Five fail-closed checks in order: destination on denylist (case-insensitive), destination on allowlist when non-empty, value at-or-below `max_value_wei_per_tx`, calldata empty (non-native blocked until ERC-20 decoder lands), projected daily spend at-or-below `daily_spend_cap_wei`. Daily-spend sums non-dry-run `action` rows from the trailing 24h via the audit log; `audit_log=None` skips this for unit tests. 13 stage tests cover every branch
- [x] Stage 3 - Tenderly Simulation: dry-run the tx, parse state diff, fail closed on revert or unexpected balance change — `napg.agentshield.stages.tenderly.build_tenderly_stage(...)` returns the Stage 3 callable. `TenderlySimulator` POSTs to `/api/v1/account/{slug}/project/{slug}/simulate` with `network_id` (84532 Sepolia / 8453 mainnet), `from`, `to`, `value`, `input`, gas limit 100k. `_parse_outcome` reads only the four fields the stage decides on (`simulation.status`, `transaction.status`, `transaction.error_message`, `transaction.gas_used`); the rest of the rich response is ignored. Fail-closed on: transport error (httpx exception or non-200), `simulation.status == false`, `transaction.status == false` (carries the revert message), or `gas_used` outside the 21k–200k native-transfer window when `data == "0x"` (defense against accidentally landing on a contract-call path). Full state-diff parsing (sender/receiver balance deltas) deferred to Phase 5 — Phase 2 mitigation is dust-cap (Stage 2) + env-pinned safe address. Live shape verified 2026-05-20 against Sepolia Tenderly endpoint. 10 tests, mocked HTTP via `httpx.MockTransport`
- [x] Stage 4 - Honeypot Detection: BUY-then-SELL simulation on the target token before any real swap — `napg.agentshield.stages.honeypot.build_honeypot_stage(simulator=, cache=)` returns the Stage 4 callable. Phase 2's only action is `migrate_to_safe` (native ETH transfer), which has no target token, so the stage passes trivially for `data == "0x"` and fails closed for any non-native calldata (which Stage 2 also blocks). The token-aware BUY-then-SELL probe lands with Phase 4 token-handling actions; the stage's external signature and the `HoneypotCache` already accept the future wiring. `HoneypotCache` is keyed by `(address, codeHash)` so a contract upgrade implicitly invalidates the entry; `evict_older_than({addr: live_hash})` drops anything whose stored hash no longer matches. 8 tests cover the native pass-through, the non-native fail-closed, and the cache contract
- [x] Centralise the four stages behind a single `validate_or_die(tx)` interface used by every action — `napg.agentshield.validate_or_die(intent)` is the pipeline. `TxIntent` is the frozen Pydantic input; `ValidationResult` aggregates per-stage `StageResult`s; `ValidationFailure` raises with the full result on any failed stage. Order: kill-switch → Intent Judge → Policy → Tenderly → Honeypot. First failure short-circuits. A `validation` audit row lands on every call (pass, fail, or kill-switched). Stage callables are injectable; production defaults raise `NotImplementedError` so the pipeline is fail-closed until each substep lands its stage. The "used by every action" wiring into `napg.actions.migrate_to_safe` + the CI grep test lands at the final Phase 2 integration substep, once all four stages exist
- [x] Add policy-config file with sensible testnet defaults — `agent/config/policy.toml` ships with 0.001 ETH per-tx cap, 0.005 ETH rolling-24h cap, empty token + destination allowlists. `napg.agentshield.policy.load_policy(config_path, public_key_path)` parses + verifies in one call; the `PolicyConfig` Pydantic model normalises every address to lowercase 0x-hex
- [x] Add denylist-loader (start with a static list, leave room for a feed) — `agent/config/denylist.toml` ships with zero-address + `0x...dead` burn address; `napg.agentshield.policy.load_denylist(config_path, public_key_path)` returns a frozen `Denylist`. Feed support and >24h staleness rejection land with the signed-feed work in a later phase (see Security item below)

### Troubleshooting
- **All transactions blocked by policy** -> caps misconfigured or env mismatch -> diff `policy.toml` against the env's intended config; run the policy unit-test suite to surface the failing rule.
- **Tenderly simulation always reverts on a legit-looking tx** -> simulation context is stale or wrong chainId -> set simulation block to head, double-check `network_id`; reproduce with a known-good tx hash first.
- **Honeypot probe rejects a legit token** -> token has non-standard transfer hooks (rebasing, fee-on-transfer) -> capture the failure trace, evaluate as a manual review case; if accepted, allowlist with an audit-log note explaining why.
- **Kill-switch engaged but signing still happens** -> wallet code bypassed `validate_or_die` -> grep `wallet.sign`, `wallet.send`, `wallet.invoke` across the repo; refactor the offender; add a CI grep test to prevent regression.
- **Policy config loader fails: "signature mismatch"** -> config edited outside the signing flow -> re-sign with the policy admin key, commit, redeploy; never bypass the loader check.
- **Denylist refresh never updates** -> feed URL changed or auth expired -> hit feed URL directly, check auth, update env var; verify signature on the new list.

### Troubleshooting
- **SIWF login loops; cookie never sets** -> third-party cookie blocking inside the Base App in-app browser -> use first-party cookies, confirm `Set-Cookie` domain matches the app's eTLD+1; check `SameSite` value.
- **Basename doesn't resolve, falls back to `0x...`** -> resolver cached a miss or RPC failed -> bypass cache, check resolver health, accept truncated-address fallback as graceful degrade.
- **Passkey prompt never fires** -> origin mismatch between manifest and deployed URL -> verify `manifest.json` `origin` and `relying_party_id` match the deployed domain exactly (including trailing slash).
- **EIP-5792 batch reverts on the second op** -> sponsored gas exhausted mid-batch or nonce conflict -> check paymaster balance, reduce batch size, ensure ops are nonce-independent.
- **CSP blocks a legitimate inline script** -> nonce not propagated -> generate nonce per-request in the layout, pass via header and script attribute.
- **Rate-limiter blocks the legitimate user** -> keying by IP behind a CDN -> key by `X-Forwarded-For`'s real client IP (validate CDN authenticity first) or by fid.
- **Mini-app doesn't show up in Base App directory** -> manifest validation failed -> hit `https://base.dev/manifest/validate` (or local validator), fix reported issues, resubmit.

## Phase 4 (Wk 5): Monetization and Attribution

Turn the agent into a revenue surface — paid Assurance Reports (x402),
sequencer-reward attribution (Builder Code / ERC-8021), and Guardian Mode
entitlements — without weakening the AgentShield posture, and with every payment
and signed report landing in the append-only audit log.

**Sequencing rationale:** reporting identity first (everything signed depends on
it) -> x402 delivery -> revenue accounting -> Builder Code -> Guardian Mode -> MEV
gate for token actions -> treasury doc. Each group lands with its own tests and a
threat-model delta before the next. Security is built into each layer as it lands
(see the cross-cutting baseline), not bolted on at the end.

**Kickoff decisions — LOCKED 2026-06-27** (resolving the open questions in [docs/design/phase-4-mev.md](docs/design/phase-4-mev.md#7-open-questions-for-phase-4-kickoff)):
1. **MEV submission: pluggable seam, default standard Base RPC.** Flashbots Protect does not support Base (June 2026) and Base has no public mempool, so the frontrunning surface is already limited. `config.py` gets a protected-endpoint field that defaults to the standard Base RPC (CDP-managed submission); the *hard* MEV bound is the on-chain `min_out_wei` (Stage 2) + Stage 3 state-diff, not the endpoint. Circuit-breaker fallback per `monitor/resilience.py`; no silent fallback to an unprotected path. Repoint at a private endpoint when Base infra / TEE-ZK sequencing matures (NAPG benefits with no code change).
2. **First token action is transfer-only.** Safe-rotation moves already-held assets (near-zero MEV, like `migrate_to_safe`). The full Group E gate still lands defensively so any *future* swap is unsignable without protection. A real DEX swap is added only when safe-rotation must convert a depegging asset.
3. **`max_slippage_bps` default = 50 (0.5%).** ~10x the observed Aerodrome USDC/USDT spread (~5 bps) — bounds loss while leaving headroom so legit stable rotations don't revert. Per-pair override for volatile pairs added later.

**Hardening decisions — LOCKED 2026-06-28** (from a second-round external review; docs in this PR, implementation tracked below):
4. **Tenderly-outage migration = degraded controlled override.** Normal ops stay fail-closed. When Tenderly is unavailable AND the action is `migrate_to_safe` to the allowlisted safe address, a narrow override applies: native transfer only (no swaps/approvals/contract calls), value bounded by Stage 2 caps, mandatory audit event, **human approval required** (autonomy yields to a human gate precisely when the deterministic sim gate is gone). Local anvil-fork simulation is the durable Phase 5 replacement. Spec in [docs/runbooks/infra-outage.md](docs/runbooks/infra-outage.md). **IMPLEMENTED** (`napg.override`): `MigrationOverride` + `check_override` (fail-closed constraints: migrate-only / native-only / armed-safe destination / two-step wait / TTL expiry), `build_override_stage` substitutes *only* the Tenderly stage in `build_migration_override_validator` — every other AgentShield stage still runs. Bounds (`migration_override_wait_seconds` 60s, `migration_override_ttl_seconds` 30min) are signed `PolicyConfig` fields. CLI two-step: `napg override arm --approver --justification` (records `migration_override_armed`) then, after the wait, `napg override execute`. 14 tests; `override.py` 100%.
5. **Maximum acceptable Base outage = 24h (launch assumption).** Drives treasury policy: 100% on-Base treasury is acceptable for launch given a 24h tolerance; tighten (cross-chain/off-chain reserves) if that assumption changes. See [docs/treasury-policy.md](docs/treasury-policy.md).
6. **Intent Judge model diversity = different Claude model. IMPLEMENTED.** Stage 1 Intent Judge defaults to `claude-haiku-4-5-20251001`, the planner/reasoner to `claude-opus-4-8` — partial decorrelation of the two LLM layers without breaking the locked "direct Anthropic SDK" decision or adding a provider. Both are configurable (`NAPG_INTENT_JUDGE_MODEL` / `NAPG_REASONER_MODEL`); `build_production_validator` + the override validator pass `settings.intent_judge_model`, the CLI passes `settings.reasoner_model`. Defense-in-depth only: Stage 2 (deterministic) remains the source of truth — the judge is an LLM *opinion*, never authoritative. A test asserts the two defaults differ.

### Troubleshooting
- **x402 endpoint returns 402 forever, even with a valid payment** -> facilitator address misconfigured or wrong chain -> check the x402 server config; hit `/healthz` on the facilitator; verify the payment landed on the correct chain.
- **Builder Code missing from on-chain calldata** -> a tx-construction path bypassed the helper -> grep all call sites; refactor offenders; add CI test asserting the suffix is present on every NAPG-originated tx.
- **Assurance Report signature fails verification at the consumer** -> wrong key version or key rotated mid-report -> check key-rotation log; re-sign with the active key; publish the consumer-facing public key with a `kid` for future rotations.
- **Same payment delivered two reports** -> idempotency key missed or storage cleared -> persist idempotency keys with at least 30-day retention; reject duplicates at the API edge, not deep in the handler.
- **Revenue audit doesn't match onchain receipts** -> off-by-one in pagination or a missed event -> re-run the reconciliation from the last known-good block; never paper over the diff, find the missing event.
- **Legitimate stable-pair swap keeps reverting on minOut** -> `max_slippage_bps` set too tight for the observed spread -> tune against the Aerodrome USDC/USDT spreads the 0x probe records; never widen it past the point where it stops bounding loss.
- **Stage 3 blocks a swap the quote said was fine** -> stale or hostile quote, or the state-diff parse is reading the wrong balance delta -> confirm the simulated received amount maps to the right token/recipient; trust the simulation over the quote and fail closed.
- **Swap submitted but no MEV protection applied** -> a submit path bypassed the protected endpoint -> all token-action submission must route through the configured endpoint after `validate_or_die`; the native-transfer path is the only one allowed to use the default RPC.

## Phase 5: Validation, operational readiness, and mainnet launch

**Stance: Phase 5 is a validation and operational-readiness phase, not a feature
phase.** Phases 0-4 answered "can we build this?"; Phase 5 answers "can we prove
this deserves to be trusted with real money?" — which takes evidence, operations,
incident response, audits, customers, and production telemetry, not 5,000 more
lines of code.

> **FEATURE FREEZE.** No new protocols, chains, tokens, or agent capabilities
> until the full chain — observation -> simulation -> authorization -> execution —
> is validated end to end. **Swap authorization stays frozen** until E3's parser
> passes its shadow-mode security review (W1). Adding capability before the
> existing one is proven is the failure mode this phase exists to prevent.

### Substeps (validation workstreams)

**Sequencing decision (2026-07-20): W8 is front-loaded and runs concurrent with
W1.** Phases 0-4 shipped a technically complete agent with zero revenue signal —
nobody has paid $1. That makes *commercial* demand, not the E3 parser, the
largest unproven risk in the whole project. But W1's gate is elapsed-time-bound
(>= 1 week AND >= 1000 shadow sims), so its clock should start ticking now and
then accrue data passively. The active-effort priority during that collection
window is W8: put the working Phase-4 agent in front of real buyers. The two do
not compete for the critical path — W1 waits on wall-clock, W8 waits on the
builder. If W8 finds no buyer for the autonomous-migration thesis, that redirects
W1-W7 (e.g. sell alerts-only, defer the moat) *before* more is built on it. This
does not touch the FEATURE FREEZE: W8 is discovery and demos of what exists, not
new capability.

**W1 — Validate E3 against reality (P0; the biggest technical unknown).** The
authorization-critical state-diff parser, proven before it ever authorises. Per
[docs/design/e3-state-diff-shadow-mode.md](docs/design/e3-state-diff-shadow-mode.md):
- [ ] Stand up the first real token action (prefer the lowest-MEV form — a
  transfer-style safe-rotation, kickoff decision 2 — or a single constrained
  Aerodrome USDC/USDT swap purely to generate shadow data)
- [ ] Implement the Stage 3 parser in **shadow mode**: store the raw Tenderly
  payload (`swap_simulation` audit kind), parse it, record parsed-vs-realized —
  **never sign on it**
- [ ] Collect >= 1 week AND >= 1000 simulations of parsed-vs-realized data
- [ ] Written security review of the parser + the collected data (property/fuzz
  tests green, schema version-pin in place, fail-closed verified)
- [ ] Only then: parser becomes authoritative; swap authorization can unfreeze

**W2 — Live treasury poller (P1; security-critical).** The Group F engine is only
as good as its observations.
- [ ] On-chain balance poller producing `TreasuryPosition`s; writes

### Troubleshooting
- **Agent process restarts in a loop on Fly** -> OOM, audit DB write contention, or crashing on startup -> `fly logs`, check memory limit, profile DB writes; bump machine size only after profiling, not before.
- **Audit DB grows unbounded, disk near full** -> no archival policy -> implement monthly archive to cold storage; never truncate the live DB without an archived copy verified.
- **Mainnet tx repeatedly reverts** -> gas estimation stale, paymaster drained, or RPC selecting a bad fork -> check gas oracle, paymaster balance, switch RPC; if paymaster drained, fall back to user-pays gracefully.
- **False-positive breach migrates real funds** -> threshold too tight or oracle compromise -> engage kill-switch immediately; review audit log; tune threshold; consider rollback only via documented recovery path.
- **Backup restore produces a corrupt SQLite file** -> backup not consistent (e.g. mid-write copy) -> use `sqlite3 .backup` or LiteFS-style snapshotting, not `cp`; re-test.
- **Farcaster cast publishing fails silently** -> signer UUID rotated or Neynar quota hit -> check Neynar dashboard, refresh signer, re-queue; alert if queue depth >N.
- **Status page shows green but real users report breakage** -> health check too shallow -> deepen the check (synthetic transaction against a sentinel pool), not just a 200 on `/healthz`.
- **Kill-switch engaged but a tx still landed onchain** -> race between signing and switch propagation -> investigate which order; tighten switch propagation to <1 sec; document as a P0 incident regardless.
